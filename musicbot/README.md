# MusicBot

База — [Remix для Fluxer](https://github.com/remix-bot/fluxer/tree/fa5bc68f16ed191aa25a6ee5dcee09ac62009f0e). Скопируйте содержимое overlay в корень checkout Remix, а deploy — в его папку deploy. Создайте deploy/config.json на основе примера upstream и задайте instanceUrl https://darkdck.duckdns.org/api. Укажите токен и пароли локально, затем заполните MYSQL_ROOT_PASSWORD, MYSQL_PASSWORD и NODELINK_PASSWORD в deploy/.env. Для работы бота используются существующие голосовые каналы Fluxer.

Перед сборкой примените `queue-advance.patch` из корня checkout Remix. Патч восстанавливает переход по очереди после `!skip`, `!skipto` и окончания заданного фрагмента трека.

Затем примените `player-panel.patch`. Команда `!player` открывает панель с прогрессом, громкостью, очередью и недавними действиями. Следующий патч `player-buttons.patch` заменяет первоначальное управление реакциями кнопками DxD.

Примените `player-panel-auto.patch` поверх предыдущего патча. Первый успешный `!play` открывает панель автоматически. При смене трека и изменении очереди бот редактирует то же сообщение. Панель закрывается при выходе бота, по реакции ❌ или после простоя с пустой очередью.

Затем примените `empty-channel-leave.patch`. Бот выходит из пустого голосового канала после `timers.inactivityTimeout`, включая воспроизведение и паузу. Повторные проверки и смена трека сохраняют срок выхода. Возвращение слушателя отменяет выход. Для включения задайте в локальном `deploy/config.json` значение `timers.stayInVoice: false`. На сервере DxD используется `timers.inactivityTimeout: 180000` — три минуты. Режим `!247 on` позволяет оставить бота в выбранном канале.

После перечисленных патчей примените `player-buttons.patch`, затем скопируйте актуальный `overlay`. Панель автоматически появляется после `!play`; `!player` открывает её повторно. Доступны предыдущий трек, перемотка на 20 секунд, пауза/продолжение, следующий трек, перемешивание, остановка, повтор, громкость и закрытие. Смена трека редактирует то же сообщение. Основная панель не добавляет и не обрабатывает реакции.

Затем примените `player-marker.patch`: URL каждой активной панели должен явно содержать `closed=0`, а закрытой — `closed=1`. Клиенты DxD Native 2026.1108.3/4 и веб-клиент проверяют все четыре параметра метки (`dxd_player`, `paused`, `loop`, `closed`); отсутствие одного из них скрывает кнопки. Регрессионная проверка `player-marker.test.mjs` создаёт настоящий `EmbedBuilder` из ESM-входа установленного SDK, использует обёртки Remix и передаёт сериализованную метку общему клиентскому парсеру.

Для кнопок нужен [обновлённый веб-клиент](../web/music-controls) либо DxD Native 2026.1108.3 и новее. Оригинальный клиент Fluxer покажет информационный embed; команды `!play`, `!skip` и другие остаются доступны. Это расширение DxD для MusicBot, а не общая поддержка Discord message components.

Сервис управления слушает порт 8787 внутри Docker-сети `fluxer_fluxer`, без публикации порта на хосте. Добавьте содержимое `deploy/Caddyfile.fragment` перед общим обработчиком `/api/*` в конфигурацию edge и перезагрузите Caddy. `compose.yml` подключает бота к этой внешней сети. Каждый запрос проверяет пользователя через API Fluxer, доступ к сообщению, ограничения аккаунта/участника и текущий голосовой канал. Токены пользователей не сохраняются. UUID панели привязан к конкретному сообщению и истекает при закрытии или перезапуске бота.

Проверки из корня checkout Remix после применения патчей:

```sh
node --test /path/to/DxD/musicbot/empty-channel-leave.test.mjs
node --test /path/to/DxD/musicbot/player-buttons.test.mjs
node --test /path/to/DxD/musicbot/player-controls.test.mjs
node --test /path/to/DxD/musicbot/player-marker.test.mjs
```
